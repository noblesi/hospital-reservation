# Hospital Reservation

> 대학병원 진료 예약 및 관리자 운영 시스템

환자가 웹에서 직접 진료를 예약하고 예약 내역을 확인하며, 관리자는 회원·예약·의료진·진료과와 운영 통계를 관리할 수 있도록 구현한 **팀 프로젝트**입니다.

> 이 README는 팀 프로젝트 전체 기능 중 **김민성의 담당 영역과 기술적 기여를 중심으로 정리한 포트폴리오용 문서**입니다. 전체 팀 프로젝트 소스와 공용 개발 문서는 `main` 브랜치를 기준으로 확인할 수 있습니다.

> 프로젝트에 표시되는 병원명, 주소, 대표전화, 지도 좌표 등은 학습용 가상 정보이며 실제 의료기관의 공식 정보가 아닙니다.

## 프로젝트 소개

전화·방문 중심의 진료 예약 과정에서 발생하는 운영시간 제약과 예약 확인·변경의 불편을 줄이기 위해 웹 기반 예약 서비스를 구현했습니다.

사용자는 다음 흐름으로 진료를 예약할 수 있습니다.

```text
진료과 선택
    ↓
의료진 선택
    ↓
진료 날짜 선택
    ↓
예약 가능 시간 조회
    ↓
예약 신청
    ↓
예약 내역 확인 / 취소
```

관리자는 회원과 예약을 조회하고 상태를 변경하며, 의료진·진료과·게시판과 운영 통계를 관리할 수 있도록 구성했습니다.

## 핵심 구현 1. 관리자 예약 통합 관리

관리자가 여러 조건을 조합해 예약을 검색하고, 조회 결과에서 예약 상태까지 변경할 수 있도록 구현했습니다.

```text
검색 조건
   ↓
Servlet
   ↓
Service
   ↓
DAO
   ↓
Oracle
   ↓
예약 목록 / 상태 변경
```

화면의 검색 조건과 SQL 조회 조건을 연결하고, 조회·상세·상태 변경이 하나의 관리자 업무 흐름으로 이어지도록 구성했습니다.

## Troubleshooting

### Tomcat 재구동·재배포 후 의료진 이미지가 사라지는 문제

**문제**  
의료진 등록 직후에는 업로드한 이미지가 정상적으로 표시되지만 Tomcat을 재구동하거나 애플리케이션을 다시 배포하면 등록 이미지가 사라지는 문제가 발생했습니다.

**원인**  
업로드 파일이 애플리케이션의 Tomcat 배포 폴더에 저장되고 있어 재구동·재배포 과정에서 해당 영역이 다시 생성되는 것이 원인이었습니다.

```text
Application
    ↓
Tomcat Deploy Directory
    ↓
Uploaded Image

재구동 / 재배포
    ↓
배포 영역 초기화
    ↓
파일 소실
```

**해결**  
업로드 경로를 애플리케이션 배포 영역 외부의 고정 디렉터리로 분리하고, DB에는 해당 파일을 다시 참조할 수 있는 경로를 유지하도록 변경했습니다.

```text
Application
    ↓
External Upload Directory
    ↓
Uploaded Image
```

**결과**

- Tomcat 재구동 후에도 이미지 유지
- 애플리케이션 배포와 업로드 파일의 생명주기 분리
- 저장 성공뿐 아니라 재구동·재배포 이후까지 검증 범위 확장

**배운 점**  
파일 업로드는 단순히 저장 성공 여부만 확인하는 것이 아니라 **배포 환경과 저장소의 생명주기까지 고려해야 한다는 점**을 배웠습니다.

## 예약 화면 AJAX 흐름

진료과, 의료진, 날짜를 선택할 때 전체 페이지를 새로고침하지 않고 필요한 영역만 갱신하도록 AJAX를 사용했습니다.

```text
진료과 선택
   ↓
Ajax 요청
   ↓
Servlet → Service → DAO → DB
   ↓
의료진 목록 갱신

의료진 선택
   ↓
Ajax 요청
   ↓
진료 가능 날짜 갱신

날짜 선택
   ↓
Ajax 요청
   ↓
예약 가능 시간 갱신
```
